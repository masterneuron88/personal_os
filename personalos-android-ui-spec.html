Design decisions and why

Two screens, one bottom bar

No drawer, no nested navigation. Everything is one tap from anywhere. This is a companion app used while walking around, not a dashboard — depth is the enemy.

Actions live on the card

Done and Postpone are visible buttons, not swipe gestures. Swipes look elegant and are undiscoverable; buttons are honest and simpler to build.

Comment is an icon, not a field

The card stays clean. Tapping the icon opens a bottom sheet with the same voice-or-type affordance as Capture, so there is one input pattern in the app rather than two. When a comment exists, the icon takes the accent color and the comment text shows inline on the card — so you can see which items have notes without opening anything.

Capture has no Save button

Entries save automatically. The tradeoff is that there is no discard — every started entry is stored, including stray half-thoughts. That is the correct trade for zero-friction capture, but the auto-save trigger must be defined explicitly before building (see open questions).

Recent entries are feedback, not a feature

With no Save button, the last-24-hours list is how you know the thing actually saved. It also surfaces the offline queue state honestly rather than failing silently.

No category picker at capture time

Deliberate, carried over from the original plan. Categorization happens later in the analysis phase, not at entry time.

Status pills

Status reuses the same pill shape. pending shows no pill (absence is the default state). in_progress uses the me purple. postponed uses the wealth amber. done shows no pill — the row dims to 55% opacity and the title gets a strikethrough instead.

Two weights only — 400 and 500. Nothing heavier. Sentence case everywhere, never title case.

Spacing and shape

  • Corner radius: 8dp on cards, buttons, pills and fields; 14dp on the bottom sheet top corners
  • Card padding: 10dp vertical, 12dp horizontal
  • Gap between item cards: 8dp
  • Screen edge padding: 12dp
  • Borders: 1dp, low-contrast hairline — never heavy dividers
  • Mic button: 64dp circle on Capture, 46dp in the comment sheet

Dark mode

Mandatory, not optional. Every color above has a dark counterpart. Never hardcode a hex in a composable — read from the theme so both modes work from one definition.

Open questions before building

  • Auto-save trigger. With no Save button, when exactly does a capture entry persist? On speech end, on leaving the screen, on a typing debounce, or a combination. Undefined behaviour here means lost or duplicated entries. Logged as backlog item 14.
  • Attachments. Screenshots, PDFs and spreadsheets in both capture and comments. This needs VM file storage, an upload endpoint, and binary handling in the offline queue — the same cost in both places, so defer both or neither. Logged as backlog item 13.
  • Postpone semantics. Does postpone move the item to a later time today, to tomorrow, or just flag it? The backend has the status value but not the rule.
  • Which list feeds Today. routine_items, planning_items, or both merged into one list.
